# Support keys used by references/gpu-canvas-and-frames.md

Checked: 2026-09-23, against the research copies of MDN browser-compat-data 8.1.2 (`raw/bcd.json`, build 2026-09-17) and web-features (`raw/web-features.json`), and the fact-check reports `verify/01` (both runs), `verify/05`, `verify/06`, `verify/07`, `verify/10` and `verify/12`. Target: Chromium only (Chrome and Edge). Other engines appear only through the Baseline column.
Rules tagged `baseline` need no row: `requestAnimationFrame`, Page Visibility, ResizeObserver (Chrome 64), IntersectionObserver (Chrome 58), Canvas 2D incl. `Path2D`, `measureText()`, `isPointInPath()`, `setTransform()` (web-features `canvas-2d`), `ctx.reset()` (web-features `canvas-reset`, Chrome 99; high 2026-06-11), `OffscreenCanvas` and `transferControlToOffscreen()` (web-features `offscreen-canvas`, Chrome 69; high 2025-09-27 for the 2D context; WebGL and WebGL2 contexts on it high 2026-03-18 per verify/10), `requestAnimationFrame` in dedicated workers (web-features `request-animation-frame-workers`, Chrome 69; high 2025-09-27), `createImageBitmap()` with its options and `ImageBitmap.close()` (web-features `createimagebitmap`, Chrome 59; high 2026-06-11), `ImageBitmapRenderingContext` (Chrome 66; high 2022-07-15), CSS Font Loading incl. `WorkerGlobalScope.fonts` (web-features `font-loading`; `fonts` in workers Chrome 69), `toBlob()` (web-features `canvas`), `convertToBlob()` (part of `offscreen-canvas`, Chrome 69).

Facts that the rules state without a version or a number (for §B, §C or §E, if the support.md writer wants them on record):

- Chromium moves an accelerated 2D canvas to the CPU after `kFallbackToCPUAfterReadbacks` (2) `getImageData` calls when `willReadFrequently` is not set; an explicit `false` keeps it on the GPU. Chrome prints a console warning on the second read. Desynchronized canvases never take this fallback. CNV-14 and CNV-17 say "after a few reads". Source: Chromium `base_rendering_context_2d.cc` (12-canvas2d-and-images.md §A; verify/12: verified).
- Chromium caches parsed canvas colors in an LRU of `kColorCacheMaxSize` (8) entries, and parsed font strings in a separate cache. The key is the internalized string, so the same text always hits; many distinct strings (per-mark opacity) miss and evict each other. Chromium's same-font early return in `setFont` runs after the style update, so JS-side skipping saves more. CNV-10 says "a few". Source: Chromium `cached_color.h`, `canvas_2d_recorder_context.cc`, `canvas_font_cache.cc`, `base_rendering_context_2d.cc` (verify/12: corrected and verified).
- WebGL active-context caps: Chromium 16 on desktop, 8 on Android, 4 per worker thread (`--max-active-webgl-contexts` overrides); WebKit 16 and 4 per worker; past the cap the oldest context is lost with a console warning. CNV-18 says "fewer WebGL contexts per worker than per page (support.md)". Source: Chromium `content/renderer/webgraphicscontext3d_provider_impl.cc` (verify/10). This belongs with the live-context cap row in §C.
- Chrome dispatches continuous input (`pointermove`, `mousemove`, `touchmove`, `wheel`) just before rAF; CNV-01 relies on it. Source: https://developer.chrome.com/blog/aligning-input-events (verify/06: verified).
- Chrome's Energy Saver lowers the frame rate, so animations that assume 16.7 ms per frame run at half speed; CNV-03 relies on it. Source: https://developer.chrome.com/blog/memory-and-energy-saver-mode (verify/06: verified).
- Chrome desktop no longer falls back to SwiftShader, so `getContext('webgl2')` can return `null` on machines without a usable GPU; CNV-05 asks for a `null` check. Source: https://chromestatus.com/feature/5166674414927872 (verify/10).
- `createImageBitmap()` `imageOrientation` accepts only `from-image` (Chrome 112) and `flipY`; BCD lists `none` as supported nowhere (verify/07). CNV-19 names the two values without a version.
- `ctx.filter`: Chrome 52, not in Safari (BCD). CNV-12 only says to keep it out of per-frame drawing, so it needs no row.
- `ImageDecoder` (web-features `webcodecs`, Chrome 94) was considered for animated images and left out of the CNV rules.
- Chrome canvas hibernation: accelerated 2D canvases in a hidden page are snapshotted to CPU memory after a random delay of up to 4 minutes (`kMaxHibernationDelay`) and compressed after 5 minutes (`kBeforeCompressionDelay`), so the first frame after a long absence pays decompression and a new upload. CNV-20 says "after some minutes". Source: https://chromium.googlesource.com/chromium/src/+/main/third_party/blink/renderer/platform/graphics/canvas_hibernation_handler.h (verify/12, missing item 1).
- In Chromium, only a canvas that is connected to the document forces a style update in `font`, `fillText`/`strokeText` and `measureText`; a detached `<canvas>` returns early (`!element->InActiveDocument()`). CNV-15 says "a canvas that is in the document". Source: Chromium `core/dom/document.cc`, `core/dom/node.cc` (verify/12).
- Canvas size limits in Chrome desktop: 65,535 px per side and 16,384² px area (third-party canvas-size tests; verify/12: verified). CNV-05 says "the browser's maximum side and area".
