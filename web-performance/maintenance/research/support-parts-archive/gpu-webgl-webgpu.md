# Support keys used by references/gpu-webgl-webgpu.md

Checked: 2026-09-23, against the research copies of MDN browser-compat-data 8.1.2 (`raw/bcd.json`, build 2026-09-17) and web-features (`raw/web-features.json`), and the fact-check reports `verify/10-gpu-webgl.verify.md`, `verify/11-gpu-webgpu.verify.md` and `verify/12-canvas2d-and-images.verify.md`. Target: Chromium only (Chrome and Edge). Other engines appear only through the Baseline column.

Convention for WebGPU rows: BCD and web-features record Chrome desktop as 144 because Linux support arrived then; Windows, macOS and ChromeOS have had WebGPU since Chrome 113. The rows give both numbers where they differ.

Rules tagged `baseline` need no row: WebGL2 (web-features `webgl2`, Chrome 56, Chrome Android 58; high 2024-03-20), `WEBGL_lose_context` (web-features `webgl-lose-context`; high 2020-10-30), `webglcontextcreationerror` (BCD Chrome 9; widely available per verify/10), `createImageBitmap()` with its options (web-features `createimagebitmap`, Chrome 59; high 2026-06-11), WebGL and WebGL2 contexts on `OffscreenCanvas` (high 2026-03-18 per verify/10; the 2D context date 2025-09-27 is a different key), `EXT_color_buffer_float` (web-features `webgl-color-buffer-float`; high 2024-03-20), `WEBGL_debug_renderer_info` (web-features `webgl-debug-renderer-info`, Chrome 33; high 2019-10-19), ASTC and ETC compressed-texture extensions (web-features `webgl-compressed-texture-astc`, `webgl-compressed-texture-etc`; high, but the formats are hardware-bound). Extensions whose presence depends on the GPU and driver (`OES_texture_float_linear`, `EXT_float_blend`, `WEBGL_provoking_vertex`, `EXT_color_buffer_half_float`) always need a `getExtension()` check, so they have no row.

Facts that the rules state without a version or a number (for §B, §C or §E, if the support.md writer wants them on record):

- WebGL live-context cap (GPU-03, GPU-30): Chromium allows 16 active WebGL contexts on desktop, 8 on Android and 4 per worker thread (`content/renderer/webgraphicscontext3d_provider_impl.cc`; `--max-active-webgl-contexts` overrides). Past the cap, the context with the oldest flush is lost and the console prints "WARNING: Too many active WebGL contexts. Oldest context will be lost." A force-evicted context whose page called `preventDefault()` comes back only when an active context is garbage-collected (`RestoreEvictedContext`). WebKit: 16, and 4 in workers. Source: verify/10 (Chromium and WebKit source).
- SwiftShader (GPU-01, GPU-34): Chrome desktop no longer falls back to SwiftShader for WebGL from milestone 139 (chromestatus 5166674414927872, "Deprecated"); `getContext('webgl2')` returns `null` without a usable GPU. Windows keeps SwiftShader or WARP only for devices with no GPU or a blocklisted GPU; mobile never used it. `--enable-unsafe-swiftshader` and `--use-angle=swiftshader` are test switches whose results differ by platform (15-gaps-round-2, unchecked; the milestone is confirmed by verify/10).
- `GPUAdapterInfo.isFallbackAdapter` (GPU-01): Chrome 136; always `false` on user devices, because Chrome has not shipped fallback adapters (Chrome 136 post). The old `GPUAdapter.isFallbackAdapter` was removed in Chrome 140.
- Adapters (GPU-29): from Chrome 140 a second `requestDevice()` on one adapter rejects (Safari 26 returns a lost device instead); adapters can also expire at any time (spec). After 2 GPU-process crashes within 2 minutes Chrome blocks new adapters for the page, and after 3 within 2 minutes for all pages; a shader that runs about 10 s trips the watchdog and loses the device (toji device-loss; verify/11).
- `powerPreference` (GPU-04): BCD says Chrome respects the WebGL hint on macOS only; on Windows, Chrome's WebGPU `powerPreference` has no effect (Chrome troubleshooting page); on dual-GPU macOS on AC power, Chrome returns the discrete GPU when no hint is given (Chrome 115; BCD `api.GPU.requestAdapter.discrete_adapter_default_ac`).
- Chrome implements WebGL `finish()` as a flush (`WebGLRenderingContextBase::finish()`, "Intentionally a flush, not a finish"). GPU-32, GPU-44.
- `GPUUncapturedErrorEvent` is exposed on `(Window, Worker)` in the current spec; the older `design/ErrorHandling.md` said Window only (verify/11). GPU-33.
- Views over resizable `ArrayBuffer`s (and Wasm `toResizableBuffer()` memory) throw `TypeError` in `writeBuffer()` and `writeTexture()`, because WebGPU's `AllowSharedBufferSource` lacks `[AllowResizable]`; measured in Chrome 152 (08-v8-batch-08 and 09-v8-consolidated, unchecked; listed by verify/11). GPU-08.
- `copyExternalImageToTexture()` from `HTMLImageElement` or `ImageData`: Chrome 118 only (BCD experimental); the rules use `ImageBitmap` and canvas sources, which need no row.
- web3dsurvey shares, read 2026-09-23 (the page shows no date window): `MAX_TEXTURE_SIZE` at least 4096 in 100% and at least 16384 in 86% of WebGL2 reports; `EXT_color_buffer_float` 99.94%; `OES_texture_float_linear` 90.58%; `EXT_float_blend` 93.76%; `EXT_color_buffer_half_float` 92.37%; `WEBGL_provoking_vertex` 76.86%; `MAX_CLIENT_WAIT_TIMEOUT_WEBGL` of 1 s or more in 7%. GPU-04, GPU-24, GPU-27, GPU-37, GPU-43.
- §E (do not use): power-of-two textures as a WebGL2 rule (a WebGL1 limit only; the design already lists it).
