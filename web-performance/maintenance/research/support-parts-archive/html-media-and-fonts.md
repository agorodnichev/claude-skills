Facts the rules state without a version (for §B, §C or §E, if the support.md writer wants them on record):

- `loading="lazy"` on `<img>` and `<iframe>`: Chrome 77, Edge 79; web-features `loading-lazy` widely available (low 2023-12-19, high 2026-06-19). MEDIA-05 is tagged `baseline`.
- Chromium lazy-load distances (`settings.json5` on `main`, verify/16-01): images 1250 px on 4G, 2500 px on 3G, 6000 px on 2G, 8000 px on slow-2G and offline, 3000 px unknown; frames 2500, 3500, 6000, 8000 and 4000 px. Horizontal scrollers use the same distances since Chrome 121. Lite mode (automatic lazy iframes) was removed in Chrome 100. MEDIA-05.
- Chromium image priority: since Chrome 117, the first 5 images larger than 10,000 px² that the preload scanner finds start at Medium (`kBoostedImageTarget = 5`, `kSmallImageMaxSize = 10000` in `resource_fetcher.cc`); an explicit `fetchpriority` turns the boost off for that image (verify/16-01). MEDIA-02.
- Chromium ignores `rel=preload` in a `Link` header on subresource responses (`kRestrictLinkHeaderOnSubresource`, on by default); it still works on the document response and in 103 (verify/16-01). MEDIA-01 (through HTML-12).
- width/height to aspect-ratio mapping: Chrome 79 (BCD `html.elements.img.aspect_ratio_computed_from_attributes`, also `video`; not `iframe`); `width`/`height` on `<source>`: Chrome 90; `aspect-ratio`: widely available (high 2024-03-20); `object-fit`: widely available (high 2022-07-15). MEDIA-04.
- WebP: widely available (high 2023-03-16). JPEG XL: not in Chrome by default (flag only; chromestatus 5114042131808256 lists a ship stage at Chrome 155, due 2026-10-06, so re-check). MEDIA-03 (key `avif`, row above) does not use JPEG XL.
- `imagesrcset`/`imagesizes` on `<link rel=preload>`: Chrome 73, Edge 79; web-features `preloading-responsive-images` widely available (high 2026-06-11). `image-set()` with `type()`: Chrome 113 (Chrome 20 to 112 prefixed or partial, `url` and `x` only); web-features `image-set` widely available (high 2026-03-18). MEDIA-13.
- `HTMLImageElement.decode()`: Chrome 64; `decoding` attribute: Chrome 65; both widely available (high 2022-07-15, verify/12 corrected the date). MEDIA-06.
- `font-display`: Chrome 60; widely available (high 2022-07-15). The preloaded-`optional` 100 ms render hold: Chrome 83 (web.dev preload-optional-fonts). MEDIA-08.
- WOFF2 in `@font-face`: Chrome 36. `system-ui`: widely available (high 2024-03-07). `font-variation-settings`: widely available (high 2021-03-05). `unicode-range`: all engines. MEDIA-10.
- `preload="metadata"` is the default for `<video>` in Chrome desktop since Chrome 64 (chromestatus 5682169347309568, verify/02). MEDIA-11.
- LCP heuristics in Chromium (metrics changelog, verify/16-03): elements with opacity 0 ignored (Chrome 86), full-viewport elements ignored (Chrome 88), removed elements stay candidates (Chrome 88), images under 0.05 bits per displayed pixel ignored (Chrome 112), transparent text ignored (Chrome 130), video first frame counts (Chrome 116, UKM first), prompt video entries (Chrome 151). MEDIA-14, MEDIA-16, MEDIA-11.
- Cross-origin LCP `renderTime` without `Timing-Allow-Origin` is coarsened, not 0: Chrome 133, Firefox 141, Safari 26.2 (BCD `api.LargestContentfulPaint.renderTime.cross-origin`, verify/16-03). Resource Timing sizes stay 0 without TAO. MEDIA-18.
- Lighthouse 13 (2025-10-10) removed `offscreen-images`, `preload-fonts`, `uses-rel-preload` and `third-party-facades`; `lcp-discovery-insight` replaced `prioritize-lcp-image` and `lcp-lazy-loaded`; `image-delivery-insight` replaced the image-format and image-size audits (it skips savings of 4096 bytes or less). Lighthouse 12.6.1 (in LHCI 0.15.1) still has `third-party-facades` (verify/16-03, verify/16-05). The rules name only the DevTools insights (`LCPDiscovery`, `ImageDelivery`, `FontDisplay`, `CLSCulprits`).

Not used as a rule (for §G or §F, if wanted): the design's MEDIA-07 draft line "no `fetchpriority` on fonts" has no source in the notes or the verify reports, so the rule leaves it out.
