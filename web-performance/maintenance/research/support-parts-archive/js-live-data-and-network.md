Facts that the rules state without a version (for §C or the notes of the rows above):

- WebSockets and the bfcache: Chromium disconnects open WebSockets when a page enters the bfcache (Chrome 149; the blink-dev PSA says 148) and fires `error` and `close` on restore, so pages must reconnect in `pageshow` (chromestatus 5068439115923456; verify/07 and verify/17 "Missing but important"). Rules: DATA-02 Avoid, DATA-10 Avoid; home LIFE-07.
- Energy Saver freezing: from Chrome 133, with Energy Saver on, Chrome freezes a hidden, silent, CPU-heavy browsing context group after 5 minutes; WebSocket handling stops too (verify/06, verify/07). Rule: DATA-10 Avoid; home LIFE-06, LIFE-08.
- DevTools network emulation and WebSockets: since Chrome 99, DevTools throttles WebSocket bandwidth and the handshake, but it adds no per-message latency (live run on Chrome 153 in 15-gaps-round-2, not fact-checked). Rule: DATA-02 Avoid; measure.md owns the test advice.
- Service worker startup: about 50 ms on desktop, about 250 ms on mobile, over 500 ms in bad cases (web.dev navigation preload article; verify/07, verify/17). Chrome 115 and later skip a no-op fetch handler (chromestatus 5136946693668864). Rule: DATA-15.
- Opaque responses in Cache Storage: Chromium pads each one by `HMAC(...) % (14431 × 1024)` bytes, so 0 to about 14 MiB with a mean of about 7 MiB; there is no 7 MB minimum, whatever the Workbox docs say (`storage/common/quota/padding_key.cc`, verify/17). Rule: DATA-15 Avoid.
- Storage eviction is least-recently-used by origin, not by size; Cache Storage, IndexedDB and OPFS share one origin quota; `localStorage` has its own limit (verify/17). Rule: DATA-15 Avoid; home LIFE-09.
- SSE over HTTP/1.1: browsers cap connections at 6 per host across all tabs, and Chrome and Firefox marked the bug "Won't fix" (MDN `EventSource`; 15-gaps-round-1, not fact-checked). Rule: DATA-02 Avoid.
