## Facts that the rules state without a version

For §B (Chromium-only engine details; no fallback needed):

- `JSON.stringify` fast path: V8 13.8 / Chrome 138 and later. It runs only with no replacer and no `space`, and only for plain objects (realm's initial `Object.prototype`, fast properties, no elements), plain arrays and primitives; any other value restarts the call on the slow path. `json_stringify_fast_path` is on by default, and the indent ("gap") is still not supported on the fast path in V8 `main` (2026-09-23). Rule: V8-10. Source: https://v8.dev/blog/json-stringify ; https://github.com/v8/v8/blob/main/src/json/json-stringifier.cc
- `JSON.parse`: the parser reuses the previous sibling's map when keys and value types match; a direct-layout fast path for arrays of same-shape objects arrived in Chrome 152 (V8 commit 72a5044f96). A reviver with exactly two formal parameters is detected from Chrome 143 (commits be082f4011, 2b6d499abb), and is still about five times slower than no reviver. Rule: V8-10.
- Polymorphic inline caches: the limit was 4 maps through Chrome 153 and is 10 from Chrome 154 (V8 commit f2c89563c0; about +1% on JetStream 3). A "homomorphic" state (many maps, one field handler) was added behind `--homomorphic-ic` in Chrome 147 (ab86d353fe) and is on by default from Chrome 156 (77b7016561; Chrome 156 stable is scheduled for 2026-10-20). Rules: V8-02, V8-14.
- IC states in `--log-ic` output and the system analyzer (V8 `ic.cc`, `TransitionMarkFromState`): `X` no feedback, `0` uninitialized, `1` monomorphic, `^` recompute handler, `P` polymorphic, `H` homomorphic (from Chrome 156), `N` megamorphic, `D` MegaDOM, `G` generic. `--log-deopt` and `--trace-deopt` are developer flags. The analyzer moved to https://v8.github.io/tools/head/system-analyzer/. Rule: V8-14.
- `delete`: V8 removed the fast deletion of the last-added property in Chrome 122 (commit 389ea9be7d), so every `delete` moves the object to dictionary mode. Other dictionary-mode starts (V8 `main`): computed-key stores past `fast_properties_soft_limit` (12) out-of-object fields, 1,020 own descriptors, `JSON.parse` objects and literals with 128 or more keys, `Object.create(null)`. Rule: V8-02.
- Pointer compression (Chrome 80 and later, 64-bit desktop and Android): tagged slots are 4 bytes and small integers have a 31-bit payload (about ±1.07 billion). Official Node builds do not use pointer compression: 8-byte slots and 32-bit small integers. Rules: V8-03, V8-04.
- Elements kinds: V8 `main` has about 40 kinds (`kElementsKindCount` 42); six fast kinds matter here (packed or holey × small integer, double, any). Since Chrome 135, an `Array.prototype.fill()` over every element of an array with its initial map moves it to the best packed kind (commit 785a0f64). Rule: V8-04.
- Regular expressions: from Chrome 152, V8 compiles a new pattern to native code on its first use (commit 4b2ab5e9cf); Chrome 79 to 151 interpreted it first. The compilation cache for patterns has 2 generations. The linear-time fallback is an experimental flag, off by default (50,000 backtracks when on); it never handles the `i`, `u` or `v` flags or backreferences, and since recent V8 it handles non-capturing lookbehinds (verify/09 corrected). Rule: V8-08.
- Sorting: `Array.prototype.sort` is stable (Chrome 70, TimSort; required since ES2019). V8 switched to PowerSort in Chrome 149 (commit 8899b945f6), with the same behavior on presorted input. Chrome 149 also inlines an insertion sort for packed arrays of at most 16 elements with a comparator known at the call site (66a3f1e94d); from Chrome 153 all receiver maps must share one elements kind (e0562d87ad; verify/09 corrected the milestone). The default typed-array sort (`std::sort`) is not stable. Rule: V8-12.
- `Object.assign({}, src)` takes a fast clone path when the target is a fresh empty object from the current realm and the source is a fast plain object, since Chrome 129 (commit b71404f1c8; verify/09 "disputed" the old "spread, not assign" rule). Myth line in v8-hot-code §H.
- BigInt: TurboFan lowers 64-bit BigInt operations with deopt on overflow since Chrome 108 (fced4e9e35), and keeps `BigInt64Array` loads and stores unboxed since Chrome 111 (b53f4d8247); Maglev got BigInt specializations in Chrome 151 (ae67ffb8a7). Code that is not optimized still allocates a BigInt per operation. Rule: V8-05.
- Tiers in V8 `main` (2026-09-23): feedback vector after about 8 calls (Sparkplug), Maglev after about 400 calls (1,000 on Android), TurboFan after about 3,000; loops tier up by on-stack replacement (budget multipliers of about 100 and 500). Turbolev is off by default. Rule: V8-13.
- `Intl` caching: V8 caches one ICU object per kind only when `locales` is a string or `undefined` and `options` is `undefined`, and keeps only the most recent entry per kind (`intl-objects.cc`, `isolate.cc`). `Intl.NumberFormat.prototype.formatRange` is Chrome 106; `Intl.DateTimeFormat.prototype.formatRange` is Chrome 76 (verify/09 corrected). Rule: V8-09.
- Stack traces: lazy source positions are the default (`v8_enable_lazy_source_positions`), so the first `.stack` of a function reparses it; `Error.stackTraceLimit` (default 10) is non-standard. Rule: V8-15.

For §C (engine and tool facts):

- `performance.now()` resolution in Chromium: 100 µs, or 5 µs when the page is cross-origin isolated (MDN; verify/07 corrected the per-engine values). Rule: V8-13.
- The per-site setting "JavaScript optimization & security" exists since Chrome 133; users of Google's Advanced Protection have it off by default. With it off (`--disable-optimizing-compilers`), V8 runs no Maglev or TurboFan and Wasm runs Liftoff code only; Sparkplug stays. Source: https://blog.google/security/advancing-protection-in-chrome-on/ Rule: V8-17.
- Chrome and Edge on iOS use WebKit and JavaScriptCore, not V8 (App Store Review Guideline 2.5.6; alternative engines only under the EU and Japan entitlements), so V8 thresholds do not apply there (verify/09 "Missing but important" 2). Source: https://developer.apple.com/app-store/review/guidelines/#2.5.6 . Used in the v8-hot-code header.

For §F (myths; v8-hot-code §H has one line each):

- "`try`/`catch` stops optimization": obsolete since V8 5.9 / Chrome 59 (Ignition and TurboFan support the whole language); throwing and stack capture are the costs. https://v8.dev/blog/launching-ignition-and-turbofan
- "Cache `array.length` before the loop": the surveys (patterns.dev `js-performance-patterns`, Vercel `react-best-practices` review) call it a no-op in modern JITs unless a profile shows otherwise; no primary V8 source measures it. The V8 elements-kinds post notes that `for…of` and `forEach` perform about like a classic `for` loop. https://v8.dev/blog/elements-kinds
- "`let` and `const` are about 10% slower than `var`": mostly obsolete; V8 elides TDZ checks that an earlier check dominates (`ignition_elide_redundant_tdz_checks`, 2023). https://v8.dev/blog/holiday-season-2023
- "`Object.assign({}, x)` is slower than `{ ...x }`": not since Chrome 129 (fast clone path, commit b71404f1c8).
- "Desugar spread, destructuring, `for…of` and argument padding by hand": object destructuring compiles to the same bytecode as plain loads since V8 7.8 (Chrome 78); spread and `Array.from` fast paths since V8 7.2 (Chrome 72); mismatched argument counts cost about the same as matched ones since V8 8.9 (Chrome 89). https://v8.dev/blog/v8-release-78 ; https://v8.dev/blog/spread-elements ; https://v8.dev/blog/adaptor-frame
- "Build JSON strings by hand for speed": the `JSON.stringify` fast path (Chrome 138) is more than twice as fast. https://v8.dev/blog/json-stringify
- "Hand-written promise chains beat `async`/`await`": obsolete since V8 7.2 / Chrome 72. https://v8.dev/blog/fast-async
- "A `DocumentFragment` is much faster" and "Wasm is always faster": corrections live in DOM-07 and TASK-13.
