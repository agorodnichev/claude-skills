### Do not inject style rules at runtime during rendering; ship static CSS and put dynamic values in inline styles or custom properties
- Verdict: verified
- Evidence: react.dev source: "Runtime injection forces the browser to recalculate the styles a lot more often." and "Runtime injection can be very slow if it happens at the wrong time in the React lifecycle." React WG discussion 110 (sebmarkbage, 2021-10-12): "This effectively causes a recalculation of all CSS rules against all DOM nodes every frame while React is rendering." Blink `main`: `CSSStyleSheet::WillMutateRules()` calls `contents_->ClearRuleSet()` (or copy-on-write when shared); `DidMutate()` calls `SetNeedsActiveStyleUpdate()` per owner/adopting tree scope and `InvalidateMatchedPropertiesCache()`; `StyleEngine::ApplyRuleSetChanges()` sets `changed_rule_flags = kRuleSetFlagsAll` when `kLayerRules` change and the change is not an append ("requires rebuilding all at-rule registries and full document style recalc"); `CompareActiveStyleSheets()` uses `RuleSetDiff`. The 0.67-0.95 ms numbers were not re-run (single machine).
- Evidence URLs: https://github.com/reactjs/react.dev/blob/main/src/content/reference/react/useInsertionEffect.md, https://github.com/reactwg/react-18/discussions/110, https://chromium.googlesource.com/chromium/src/+/main/third_party/blink/renderer/core/css/css_style_sheet.cc, https://chromium.googlesource.com/chromium/src/+/main/third_party/blink/renderer/core/css/style_engine.cc, https://chromium.googlesource.com/chromium/src/+/main/third_party/blink/renderer/core/css/active_style_sheets.cc

## Missing but important

1. **Playwright passes `--enable-unsafe-swiftshader` by default** for Chromium. GPU-less CI jobs get SwiftShader silently, and frame numbers then measure the CPU. Always log the renderer string. Source: https://github.com/microsoft/playwright/blob/main/packages/playwright-core/src/server/chromium/chromium.ts
2. **One popover for a whole list through the implicit anchor.** `popovertarget`/`commandfor` and `showPopover({ source })` make the invoker the implicit anchor (BCD `implicit_anchor_reference`: `popovertarget` Chrome 133, Firefox 147, Safari 26; `commandfor` Chrome 135, Firefox 147, Safari 26.2). With the new initial `position-anchor: normal` plus `position-area` (Chrome 151, Firefox 151, Safari 27), one order-ticket popover follows whichever price cell opened it. This avoids a unique `anchor-name` per row in a 1,000-row watchlist. Sources: raw/bcd.json, https://webkit.org/blog/18325/webkit-features-for-safari-27-0/
3. **`anchor-scope`** for repeated components that reuse one anchor name (per-key Baseline 2026-01-13: Chrome 131, Firefox 147, Safari 26). Without it, rows that all set `anchor-name: --price-cell` collide. Source: https://drafts.csswg.org/css-anchor-position-1/#anchor-scope, raw/web-features.json
4. **`position-area` resolves auto margins and insets to 0.** The popover centering reset is only needed in older engines or with `anchor()` insets (see item 3 correction). Source: https://drafts.csswg.org/css-anchor-position-1/ (§3.1 and changes, issue 10258)
5. **Frames track in the saved trace.** DevTools records `disabled-by-default-devtools.timeline.frame`, so the saved MCP trace, opened in DevTools, shows dropped and partially presented frames (DevTools 100). This gives trace-level frame data next to the in-page probe. Sources: https://github.com/ChromeDevTools/devtools-frontend/blob/main/front_end/models/trace/types/TraceEvents.ts, https://developer.chrome.com/blog/new-in-devtools-100
6. **`Memory.getDOMCountersForLeakDetection`** (CDP): prepares the renderer for leak detection and returns the counters in one call. It is simpler than `prepareForLeakDetection` plus `getDOMCounters` for the slope test. Source: https://chromedevtools.github.io/devtools-protocol/tot/Memory/
7. **Per-URL throttling through CDP.** `Network.emulateNetworkConditions` is now deprecated in favor of `Network.emulateNetworkConditionsByRule` (experimental, URL patterns) plus `Network.overrideNetworkState`. This can throttle only the market-data origin. Whether rules apply to WebSocket frames is not tested. Source: https://chromedevtools.github.io/devtools-protocol/tot/Network/
8. **QUIC idle timeout for preconnect over HTTP/3.** Chromium closes idle QUIC connections after 30 s by default, not 60 s. Source: https://chromium.googlesource.com/chromium/src/+/main/net/quic/quic_context.h
